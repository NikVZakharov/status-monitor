# Status Monitor

Общий Node.js-компонент мониторинга доступности. Запускает проверки, подтверждает инциденты повторными наблюдениями, хранит историю и обслуживает автономную страницу состояния вместе с `GET /status.json`.

## Граница компонента

Профиль и интерфейс принадлежат проекту-потребителю. В этом репозитории нет производственных профилей, адресов приложений или секретов. Профиль — доверенный ESM-файл из репозитория проекта; он определяет компоненты, имена env-переменных с адресами проверок, правила чтения health-ответов, обслуживание и подготовленные тексты. Он устанавливается администратором и исполняется сервером.

`src/monitor.mjs` управляет циклом проверок; `src/probes.mjs` предоставляет ограниченный HTTP-транспорт профилю; `src/status-state.mjs` сохраняет наблюдения и историю; `src/server.mjs` отдаёт статическую сборку и публичный feed. Пример контракта профиля: `examples/profile.mjs`.

## Установка релиза

Загрузите архив конкретного GitHub Release и проверьте его SHA-256 по закреплённому в репозитории проекта значению. Не устанавливайте `main` или плавающий `latest`. После распаковки выполните:

```sh
sudo ./install.sh /secure/project-status.env /secure/dist-status /secure/profile.mjs
```

Installer проверяет происхождение и SHA-256 файлов релиза, профиль и настройки до остановки службы. Он сохраняет предыдущую установку для отката, сохраняет каталог истории и существующие значения защищённого env. При неуспешной активации восстанавливает прежний runtime. Отдельное планирование перед apply не требуется.

В репозитории проекта храните `deploy/status/profile.mjs` и `deploy/status/component-release.json` с репозиторием компонента, версией, тегом, URL архива и SHA-256. Статическую страницу собирайте в проекте. Профиль не содержит секретов; Access service token при необходимости остаётся в защищённом серверном env.

Для профиля с `id: example` установленные пути:

- `/opt/promtech/example-status-monitor/` — релиз компонента, профиль, метаданные установки и `public/`;
- `/etc/promtech/example-status-monitor.env` — конфигурация с правами 0600;
- `/var/lib/example-status-monitor/` — история с правами 0700;
- `example-status-monitor.service` — отдельный systemd-процесс.

Installer сохраняет выбранный при его запуске путь Node.js в службе; при отдельном runtime добавьте его `bin` в PATH перед apply. Системный Node.js и другие приложения не обновляются.

Требуются Linux/systemd, поддерживаемая Node.js не ниже 22.16, Bash и util-linux `flock`. Listener принимает только `127.0.0.1`; существующий HTTPS proxy обслуживает домен. Установка не меняет DNS или HTTPS-маршруты.

## Настройки

Скопируйте `examples/status.env.example`. Обязательны абсолютные каталоги истории и статической сборки, loopback host, порт, интервал, timeout и срок актуальности. Профиль задаёт имена env-переменных URL через `targetVariables`. Разрешены HTTPS и loopback HTTP, без credentials/query/fragment. `STATUS_PROFILE_PATH` добавляется installer и указывает на установленный профиль. `STATUS_STATE_FILE` по умолчанию равен `observations.json`.

Опциональная пара `STATUS_ACCESS_CLIENT_ID`/`STATUS_ACCESS_CLIENT_SECRET` передаётся только на заданные адреса проверок. Redirect не выполняется. Отсутствие авторизации даёт unknown, а не доказательство отказа приложения. Ответы ограничены по размеру и времени; TLS проверяет цепочку и hostname.

Первая неудача означает degraded, вторая подтверждает инцидент. Два последовательных успеха закрывают его. Непроверяемые или устаревшие данные отображаются как unknown. История — до 30 дней и 50 закрытых инцидентов. Публичный JSON не содержит исходных ошибок, target URL, credentials или ответов приложений. Готовность HTTP/API не доказывает прохождение пользовательского сценария.

## Разработка и релизы

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm release:build
```

Release Please создаёт PR с `VERSION`, `package.json`, changelog и manifest по Conventional Commits. После его слияния публикуется тег и GitHub Release с архивом, `release.json` и `SHA256SUMS`. Артефакт содержит точный source commit и SHA-256 каждого исполняемого файла. Проекты обновляют собственную закреплённую версию отдельно; публикация релиза не меняет runtime автоматически.
